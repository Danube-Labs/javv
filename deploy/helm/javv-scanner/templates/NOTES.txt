Run a cycle now instead of waiting for the schedule. One cycle at a time per scanner holds only
for the cycles the CronJob starts itself, so pause it first and start yours when none is running:
{{- range $name := include "javv-scanner.scanners" . | fromJsonArray }}
{{- if (index $.Values $name).enabled }}
{{- $cj := printf "%s-%s" (include "javv-scanner.fullname" $) $name }}

  kubectl -n {{ $.Release.Namespace }} patch cronjob {{ $cj }} -p '{"spec":{"suspend":true}}'
  kubectl -n {{ $.Release.Namespace }} get jobs -l app.kubernetes.io/instance={{ $.Release.Name }},app.kubernetes.io/component={{ $name }}
      (wait until none of them is Running)
  kubectl -n {{ $.Release.Namespace }} create job {{ $name }}-now --from=cronjob/{{ $cj }}
  kubectl -n {{ $.Release.Namespace }} wait --for=condition=complete job/{{ $name }}-now --timeout=6h
  kubectl -n {{ $.Release.Namespace }} patch cronjob {{ $cj }} -p '{"spec":{"suspend":false}}'
{{- end }}
{{- end }}

  If a step fails, still run the last patch: a paused CronJob starts no cycle until it is resumed.

Each run first refreshes the scanner's vuln DB into its own volume, then scans every running image.
Its result shows in JAVV under Scanner status. A scanner pulls images from a private registry only
with a login in <scanner>.registryAuth.existingSecret.
